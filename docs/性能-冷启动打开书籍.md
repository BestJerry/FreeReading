# 冷启动打开长书

## 问题和测量范围

2026-11-17，用户反馈冷启动后从书架打开长书约等待 10 秒，小书较快。

原有顺序为：完整听书索引 → 进度 → EPUB 完整检查 → 阅读 Fragment。正文展示依赖整份听书数据解析完成。Readium Fragment 的构造器还会同步等待全书 positions。

本次用本地 JVM / Robolectric 分阶段测量，没有连接手机。下列毫秒数代表本地组件耗时；不代表 Android WebView 的实际首帧或手机的端到端耗时。仓库对象缓存为冷态，JVM 与操作系统文件缓存未受控。

## 修复前基线

原创合成大书为 180,000 句、102,042,416 字节索引，每句独立 source，覆盖接近用户原书的索引规模。小书为原创测试样本，29 句。

| 本地阶段 | 小书 | 原创大书 |
| --- | ---: | ---: |
| 读取书架元数据 | 0.46 ms | 2.12 ms |
| 读取进度 | 0.55 ms | 0.19 ms |
| 原始索引字节读取 | 0.15 ms | 11.96 ms |
| 冷解析完整听书索引 | 6.78 ms | 889.07 ms |
| 已持有完整索引时命中缓存 | 0.67 ms | 0.41 ms |
| 完整索引的保留堆增量 | 约 66 KiB | 约 202 MiB |

原始字节读取远小于 JSON / Locator 解析及对象构建。弱引用缓存无法消除进程重新创建后的工作。

对用户提供的 9,883,453 字节 EPUB 只做本地读取，未将其正文加入仓库：

| 本地阶段 | 修复前 |
| --- | ---: |
| ZIP 目录与 Readium 解析 | 88.70 ms |
| 重新读取全部 1836 个正文章节 | 128.05 ms |
| 首次 positions 计算 | 35.69 ms |
| 同一 Publication 的 positions 缓存 | 0.011 ms |

这两组使用不同输入，应分别解读，不相加作为端到端耗时。

## 优化边界

- 当前版本书籍先读取小型书籍记录与视觉进度，直接准备正文；听书索引在书页加载完成或用户提前要求听书时加载，共用一个延迟任务。
- 已有有效完整索引时继续复用；旧索引仍先迁移并校准进度，避免恢复到过期位置。
- 已导入私有 EPUB 使用日常阅读入口，保留 ZIP 路径、大小、格式和出版物结构检查；导入和迁移保留逐章完整可读性检查。
- 同一 Publication 的 positions 在 IO 线程提前计算，复用 Readium 原算法和缓存。
- 索引到达后补齐听书能力，保持已经显示的阅读 Fragment 和手动导航意图；提前听书、选文、关闭页面与最终保存须独立验证。
- 快速退出后重开同书，先等待上一阅读页的最终保存完成；等待放在书籍锁外，首次冷开及不同书籍不会因此等待。保存同时校验捕获时的导入代次与时间戳，旧阅读页不会覆盖重新导入或更新的进度。

## 验证

优化后，同一原创大书的轻量书籍准备为 **0.41 ms**，完整索引仍需约 **746 ms**，现在由正文显示后或听书需求触发。轻量准备没有创建完整的句子对象表，测得保留堆增量约为零（受 GC 噪声影响）。

用户提供的同一 EPUB 日常阅读打开为 **131.18 ms**，其中已包含 positions 的 IO 预计算；Fragment 后续调用 positions 命中缓存约 **0.012 ms**。本地正式计数测试确认，日常打开不再逐章读取正文，严格导入入口仍然读取所有章节。positions 数量保持 10,253，算法未变。

上述结果来自不同批次，JIT、GC、文件缓存会波动，完整索引解析本身没有因此加速。优化针对首屏依赖和重复工作，手机从点击到真实书页绘制的时间尚未实测。

基线和优化后输出分别保存在本次本地 `/private/tmp/freereading-cold-open-before-results/`、`/private/tmp/freereading-cold-open-after-results/`。性能探针保留在 [`benchmarks/cold-open/`](../benchmarks/cold-open/README.md)，与常规回归测试分开。

最终 **48 个测试类、474 条测试通过**，无失败、错误或跳过；Debug APK 构建成功，Lint 无错误（43 项 warning、1 项 hint）。其中 19 条仓库准备／保存回归、10 条 Readium 阅读入口回归、12 条真实 Activity/Fragment 冷打开回归，以及原有听书、目录、定位迁移测试均通过。

生命周期测试使用可控 Deferred 和真实 Fragment 验证加载顺序与状态；Robolectric WebView 不执行真实页面绘制，手机首帧耗时仍需独立测量。

本次使用阶段测量与成功对照检验假设：[Testing a Hypothesis](https://www.debuggingbook.org/html/Intro_Debugging.html#Testing-a-Hypothesis)。
