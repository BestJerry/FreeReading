# 中文听书语言匹配诊断

## 已观察证据

2026-11-12，荣耀 BKQ-AN00（系统报告 Android 17）：阅读已导入的 EPUB 时，应用提示没有中文离线声音；系统中文示例可以播放。

- 报错书籍的 `book.json` 中 `language` 为 `zho`。
- 默认引擎 `com.hihonor.voiceengine` 返回 3 个中文离线 Voice，`locale.language` 都为 `zh`，没有 `notInstalled` 标记。
- 对默认引擎返回的离线声音实际调用 `synthesizeToFile()` 成功，WAV 为 78,492 字节、1,634 ms。
- 作为对照，手机上的 Google 引擎返回 4 个已安装的中文离线声音；短句合成也成功（95,572 字节、1,990 ms）。

这些实验未更改系统默认语音引擎，也未改写书籍语言元数据。合成时依据引擎报告的离线标志筛选声音；没有进行飞行模式测试。

## 竞争解释与判断

| 解释 | 实验前预测 | 观察与判断 |
| --- | --- | --- |
| 默认引擎没有可用的中文离线声音 | 荣耀引擎的中文离线列表为空，或短句合成失败 | 列表非空且实际合成成功，排除 |
| 等价语言代码未归一化 | EPUB 的 `zho` 与 Voice 的 `zh` 在字符串比较时不相等，中文声音被全部过滤 | 元数据、声音列表与原代码的严格比较完全吻合，确认 |

`zho` 与 `zh` 都表示中文。直接比较 `Locale.language` 的字符串不能代表语言语义是否相同。

## 修复边界

在 TTS 声音选择边界归一化语言标签，请求语言与 Voice 语言使用相同规则。保留书写系统、地区、扩展和合法未知语言；继续过滤需要联网或尚未安装的声音。使用 Android ICU 规范化标准代码；旧版 ICU 无法识别的 bibliographic 别名（如 `chi`）使用集中标准映射。

依据：[Android ULocale 文档](https://developer.android.com/reference/android/icu/util/ULocale)、[ISO 639-2 标准代码表](https://www.loc.gov/standards/iso639-2/php/code_list.php)。

## 验证结果

- 修复前：提取原有匹配算法后运行 `zhoBookMetadataMatchesZhOfflineVoice`，API 28 的用例按预期失败，提示 `zho` 无法匹配 `zh`。
- 相关边界：API 26/28 的测试确认旧版 ICU 单独无法归一化 `chi`，使用 ISO 标准别名映射补全；书写系统、地区、Unicode 扩展、未知语言和音色排序均有回归。
- 修复后：70 项自动测试全部通过，其中语言规则在 API 26/28 分别执行；Debug APK、AndroidTest APK 构建成功，Lint 无错误。
- 原荣耀手机：`synthesizesEquivalentChineseLanguageTags` 真实调用 TTS 缓存入口，`zh-CN` 和 `zho` 都成功返回 2,059 ms 的音频，真机用例通过。
- 原书整链：在 0.1.1 阅读页点击播放，错误提示消失，按钮显示暂停，正文高亮从版权首句推进到后续句子。系统媒体会话为 `PLAYING(3)`，已播放位置为 6,483 ms，队列包含 6 项，`error=null`。
- 长时间熄屏与飞行模式测试未在本次执行；系统默认引擎保持荣耀引擎。书籍与阅读进度保留，不需要重新导入。

临时声音目录探针已移除，保留等价语言标签的真机合成回归；诊断测试包在验证后卸载。
