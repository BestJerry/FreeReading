# 音色弹窗退出诊断

## 现象与证据范围

2026-11-17，用户反馈点击听书页的「音色 · 选择音色」，弹窗出现后返回 FreeReading 书架。预期是留在音色弹窗，加载可选音色，选择或关闭后继续使用听书页。

本次使用本地 JVM / Robolectric 测试；未连接手机。手机实际音色明细和崩溃日志尚未取得，已确认的缺陷是下面可独立复现的列表崩溃。

## 实验与观察

实验前预测：若重复音色 ID 导致崩溃，同一套嵌套 Dialog 在唯一 ID 输入下应正常，在重复 ID 列表到达后应抛出列表 key 冲突异常。

`ListeningVoiceDialogRegressionTest` 复刻阅读页的全屏听书 Dialog 和内部音色 Dialog。点击入口先发布 loading，再异步写入三个音色，分别测试唯一名称及同名、不同地区与质量的输入。

修复前结果：

- 唯一 ID 的正对照通过；弹窗打开、加载、关闭后，听书页仍保留。
- 重复 ID 输入抛出 `IllegalArgumentException`，消息为 `Key "12:local.engineinstalled-local" was already used`；栈位于 `LazyListMeasure` / `SubcomposeLayout`，发生在音色列表返回后的布局阶段。
- 后端同名音色回归失败：预期两项实际四项，目录 ID 不唯一。
- 本地输入中的多个 `Voice` 能共存于集合，因为其相等性包含地区、质量等属性。Android TTS 的 `setVoice()` 加载语音时使用音色名称；应用原有 ID 也由引擎包名与音色名称组成。

正常查询服务没有启动书架或结束阅读 Activity 的代码。`stopSelf()` 负责停止服务。当前实验确认了列表异常；手机上是否发生同一个异常仍需实际崩溃记录佐证。

## 修复

- `TtsVoiceSelection.eligibleVoices()` 在原有语言、质量排序后按名称去重，保留优先级最高的元数据，保证展示和合成选择一致。
- `TtsVoiceSelection.catalog()` 按生成的 ID 去重，确保返回一个名称对应一个选择项。
- `TtsVoicePicker` 渲染前按 ID 去重，保证传入的列表也满足 Compose 的唯一 key 约束。
- 保留异步列表到达的嵌套弹窗回归，验证重复项仅显示一次、点击返回正确 ID，以及关闭后听书页仍然显示。

## 运行方式

```bash
./gradlew :app:testDebugUnitTest \
  --tests 'com.freereading.reader.ListeningVoiceDialogRegressionTest' \
  --tests 'com.freereading.audio.TtsVoiceSelectionTest' \
  --tests 'com.freereading.audio.OfflineSpeechCacheVoiceTest' \
  --no-daemon --max-workers=2

./gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug \
  --no-daemon --max-workers=2
```

使用 JDK 17；本机显式指定方式见 README。修复前基线为 4 次执行、3 次失败，唯一 ID 弹窗对照通过。

修复后，42 个测试类、397 条测试全部通过，包括重复 ID 弹窗和 API 26/28 的同名音色回归；Debug APK 构建成功，Lint 无错误（41 项 warning、1 项 hint）。本轮没有进行真机复测，保留手机实际崩溃来源的验证限制。
