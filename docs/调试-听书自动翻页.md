# 听书时原文自动翻页

用户确认按当前朗读句自动翻页。正文空间保持不变，原文页只在现有 28dp 页脚增加「自动翻页／继续跟随」按钮，播放控制仍在独立听书页。

## 原因与修复

Readium 3.1.2 的 `go(locator, false)` 已能按句子文字跨同一 XHTML 的分页。用完整 SDK JavaScript、原创长段落和真实 Chromium CSS columns 对照：所有 Locator 的 progression 都是 0，三个目标句仍能将 scrollX 从 0 推到 360、720，目标文字的真实 Range 均在视口内。因此不应根据章节百分比猜测阅读页码。

中断发生在应用的手势处理：Readium 的 drag-start 阈值仅为 6 物理像素，DPR 为 3 时手指移动 2 CSS 像素就会触发，原代码随即关闭跟随。现在超过 Android touch slop 的实际导航手势才暂时脱离跟随：分页检查横向位移，滚动同时支持纵向浏览和横向换章，与 Readium 的导航能力一致。微小抖动继续自动翻页，每个手势只报告一次。

用户开关与手动浏览意图区分保存：翻页、目录、链接和选文暂时脱离跟随，页面直接提供恢复入口。每次明确开始或恢复朗读时开启跟随，包含锁屏／耳机恢复、章节按钮及从正文选定位置起播；自然换句、倍速及音色切换沿用本次播放中用户关闭的状态。服务使用独立跟随请求标识通知阅读页，不以播放／缓冲状态跃迁判断新起播。关闭播放器不会丢弃手动选择的位置。

跟随请求按用户操作顺序编号，应用在发送播放命令前签发，服务仅在实际开始或恢复时发布；系统媒体控制直接进入服务时当场签发。手动关闭、浏览或主动恢复跟随会登记已处理水位，忽略在此之前提交但随后才到达的旧命令。下一次新起播仍可开启跟随，进程重启后旧水位不会阻止新事件。跟随请求与起播确认标识独立，不能相互代替。

同一句重新起播或恢复也会重新定位，观察播放/准备状态及播放会话。客户端签发带进程命名空间的有序起播标识，服务接受指令后原样发布，后续切句保留该标识；等待确认时禁止旧句任务拉回页面。较早的请求不能确认较晚的请求，本次及之后的新请求可解除等待。后台或旋转期间即使错过起播句，也能在回到前台时追上当前句；进程重启后丢弃无法再执行的旧等待状态。

取消选文/正文查询与等待已发起的服务请求分开，暂停不会提前解除导航门禁。平台拒绝启动或服务接受前通知失败均携带关联请求信息，保留目标句及句内偏移供重试；失败时暂停跟随，避免跳回旧音频。服务停止/销毁保留这项失败信息，后台阅读器恢复后仍可识别；正常新起播会清除旧失败。

## 本地回归

使用 JDK 17：

```bash
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug --no-daemon --max-workers=2
```

回归覆盖微小抖动、真实翻页/滚动、手势方向与非法坐标，原文页开关与恢复入口、窄屏和大字号、页脚热区，连续句及跨资源导航，同句重新起播，关闭偏好，服务确认延迟和后台/旋转错过起播句。真实 Activity/Readium Fragment 用例检查实际 `go` 调用和装饰更新；Robolectric 不执行 WebView JavaScript。

自动翻页首轮验证包含 37 个测试类、331 条测试，全部通过。起播自动跟随与命令顺序修复后的全量验证包含 52 个测试类、531 条测试，失败、错误和跳过均为 0；Debug APK 构建成功，Lint 无错误且警告数量未增加。新增回归通过真实 Hub Intent 和 Service 延后接收，确认旧起播、恢复及前后章节／句子命令不能覆盖其后的手动操作，新起播仍能开启跟随。

另用隔离的本地无头浏览器加载 AAR 内完整 Readium JavaScript，在原创 17 页内容中验证三个句子的跨页定位：scrollX 为 0、360、720，目标 Range 可见，无 JavaScript 错误或网络请求。脚本和报告留在本机临时目录，未操作手机。

翻页以朗读句的位置为单位。单个长句跨页时，在下一句开始时更新页面位置。
