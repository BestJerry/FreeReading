# 目录选择后听书起播

## 故障现场

2026-11-12，荣耀 BKQ-AN00，FreeReading 0.1.1。用户选择目录中的“第1部分”，阅读页显示正文，但主播放按钮提示“当前位置暂无可朗读文字”。

只读检查当前 WebView 与既有句子索引得到：

- 资源为 `OEBPS/Text/part0109.xhtml`，已有句子索引属于 chapter 8。
- Readium 的首个可见 Locator 返回 `cssSelector="div"`、`text.highlight=""`。
- 该 selector 对应高度为 0 的 `<div style="page-break-after:always"></div>`。
- 空 div 后是 `h1.kindle-cn-heading-1`。标题三段分别已有句子索引 175、176、177，正文从 178 开始。

## 因果与竞争解释

实验前的两个主要预测为：首个可见元素没有文字，或 DOM/索引的空白与 CSS selector 形状不一致。实际采集到的是前者：空分页 div 被当成首段，但它不产生可朗读句子。

原 Matcher 只接受文字包含关系或字面相同的 selector。空 div 没有文字，selector 也与 h1 的索引不同，因此返回 null，传播为 Toast。复现夹具同时断言原 Matcher 返回 null、源码 DOM 解析后返回当前资源的 175，不能回到整书首句。

另有独立的控制入口缺口：同一本书已有暂停会话时，主按钮只调用 toggle，忽略用户新选的章节。

真机复测还发现重开音频时的崩溃：`ProgressBarRangeInfo` 抛出 `current must not be NaN`。界面创建进度条时虽然检查过时长，但延迟执行的进度 lambda 会读取新的音频状态；准备下一次播放时，位置与时长都可能归零，产生 `0 / 0`。崩溃日志中的时间为 18:05:21，旧版 17:32:12 也有相同堆栈。

加入朗读高亮后，Readium 会在页内插入装饰 div。原分页 div 的首段 selector 因此变为 `[style='page-break-after\:always']`。浏览器能够匹配这个带转义的属性值，源码侧也必须按相同含义解析，才能让已有高亮时的“从此段听”继续找到同一个节点。

## 修复边界

- 用原始 XHTML 结构验证元素身份。空分页节点、分隔线或图片本身没有句子时，沿同一资源的 DOM 顺序查找后面的真实文字。
- CSS selector 的不同写法若解析到同一元素，按该元素的已有句子起播，不通过全局删除空格猜测。
- 对完整的带引号属性选择器，先按 CSS 字符串规则解码，再与源码中的属性值精确比较。匹配不到或匹配多个元素仍失败，不改写 id、class 或复合 selector。
- 明确的目录选择保留目标资源/fragment；主按钮在暂停状态尊重新的阅读位置。普通暂停续听保留句内偏移，正在播放时主按钮仍用于暂停。
- 页面缓存与异步请求带导航版本，手动导航会使旧缓存、旧起播任务失效。
- 目标元素不存在、歧义或无法可靠定位时返回失败；只有明确的目录资源起点请求可以从该资源首句起播。
- 进度条通过单个音频快照计算安全比例。尚无时长时返回 0，其余结果限制在 0～1；避免重开播放时产生 NaN 并触发 Compose 崩溃。

## 验证

使用 JDK 17 执行：

```bash
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug --no-daemon --max-workers=2
```

自动回归：12 个测试类、106 条测试全部通过，APK 打包成功。Lint 无错误，仍有 36 条警告与 1 条提示。

荣耀 BKQ-AN00 使用原有 EPUB、索引和进度，覆盖安装 0.1.2（versionCode 3）后的结果：

| 操作 | 观察结果 |
| --- | --- |
| 目录选择“第1部分”，点击主播放 | MediaSession 为 PLAYING、error=null；原文进度从句子 175 推进到 177 |
| 暂停后从目录选择“第1章”，点击主播放 | PLAYING，章节元数据为“第1章”，未续播旧章节 |
| 暂停后再次选择“第1部分”，点击主播放 | PLAYING，章节元数据回到“第1部分” |
| 已有朗读高亮，暂停后连续两次使用“从此段听” | 两次均重新进入 PLAYING、error=null，应用进程保持运行 |

复测结束保持暂停。没有删除或重新导入书籍。
