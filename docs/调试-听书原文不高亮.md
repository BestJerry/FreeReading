# 听书时原文句子不高亮

## 复现与预期

用户反馈《牧神记》在正常连续听书时，阅读页一直没有当前句高亮。预期是播放句子的文本与阅读器中被标记的文本相同，切句和切章后只保留当前句。

使用用户提供的本地 EPUB 做只读诊断。原书、正文摘录和诊断截图没有加入仓库，仓库回归夹具均为原创内容。本轮不连接手机；JVM 测试检查索引、真实 Activity/Fragment 生命周期与 Readium 装饰更新，独立的本地无头浏览器检查 Readium JavaScript 能否生成正确高亮。

## 实验与根因

先检验两个解释：共享索引是否丢失定位上下文，以及高亮模板或书籍 CSS 是否让标记不可见。

- 全量检查原书持久化索引中的共享来源，定位资源与对应 reading-order URL 严格相等，没有资源路由错误。
- 原始 XHTML、原书 CSS、Readium CSS、分页/滚动和夜读样式的对照中，合法 Locator 均可生成非零大小的高亮区域。高亮模板已注册。
- 进一步从实际导入后重新读取的索引抽取 Locator，原书 6 个样本中 3 个不能匹配原文；原创示例 5 个样本均成功。不能用手工选中的合法段落代替持久化定位验证。

失败章节以 UTF-8 BOM 开头。Readium 3.1.2 的 HTML 内容迭代器把解码后的字符串交给 Jsoup，字符串开头的 U+FEFF 没有被消费。Jsoup 因此把部分 `meta/title/link` 节点放入 body，既错误收录页头标题，也让正文的 `nth-child` 偏移。阅读器浏览器会消费字节 BOM，页面 DOM 不含这些额外节点。

控制实验的预测是：如果 DOM 错位是原因，只替换失败 Locator 的 selector，保留其资源、原文与上下文、样式和高亮脚本，就应恢复正确标记。实际对原索引第 91,468 句，将 `nth-child(15)` 改为去 BOM 后对应的 `nth-child(11)`，定位由失败变为成功；高亮 Range 的文本 SHA-256 与句子全文相同，生成一个装饰及非零可见区域。这证明了选择器错位到高亮失败的因果链。

另有独立的更新时序风险：Readium 先记录目标装饰，再异步计算差异。并行更新可能让旧脚本迟到；页面就绪前脚本也可能被跳过，而相同目标的后续更新变成空差异。固定装饰 ID 在跨资源移动时还可能只产生 Updated，无法移除旧资源中的标记。

## 修复

- 在 HTML 内容迭代器的读取边界仅去掉字节零位的完整 UTF-8 BOM，让索引 DOM 与浏览器一致。正文中间的 U+FEFF、无 BOM 的内容、原始 EPUB 字节与浏览器读取资源均保持原样。源码定位解析使用相同规则。
- 用每次 `PublicationOpener.open()` 的 builder 回调注册内容迭代器。首轮真实 EPUB 回归暴露了 Readium 3.1.2 构造回调未应用的问题；不能只确认工厂已编译或 helper 单测通过。
- 给正文索引增加解析版本，旧书在首次打开时从原 EPUB 自动重建；同时按资源、元素与文本上下文迁移原有阅读/听书位置。新索引、迁移进度和元数据分步原子保存，中断后可重试。
- 普通阅读进度的视觉 Locator 通常没有文字和 CSS selector，原句号是独立保存的。迁移时保留旧索引，从中流式读取该句定位作为迁移证据，并保持原视觉 Locator；最终版本提交后再清理旧索引。避免无 BOM 的旧书也从章中退回章首，同时不在内存中加载两份全书索引。
- 写入检查同时覆盖同步与原子提交结果。Android `AtomicFile` 部分提交失败只记日志，因此检查实际文件及临时/备份文件，避免索引或进度未提交就更新最终版本标记。
- 在阅读器 View 的 STARTED 生命周期内串行更新高亮，合并待处理的最新句，阻止过期请求导航。每个 View 会话首次就绪先清空装饰组，移除旧任务中断后可能遗留的 DOM 标记；每个会话和页面就绪事件使用新的装饰 ID，强制有效重画。关闭跟随仍更新高亮，结束听书清空标记。

## 回归方式

使用 JDK 17：

```bash
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug --no-daemon --max-workers=2
```

原创回归覆盖 BOM 与无 BOM、页头不进入朗读索引、重复段落的准确选择器、内部 U+FEFF 保留、旧索引和进度迁移、并发切句、跨章差异、同句页面重载、后台/前台恢复和 Fragment View 重建。

最终全套本地验证为 35 个测试类、288 条测试全部通过，失败、错误及跳过均为 0；Debug APK 构建成功。Lint 为 0 错误、40 警告及 1 提示。

实际原书验证：

- 索引从 182,937 句变为 181,101 句，剔除 1,836 个错误收录的页头标题，原 EPUB 字节不变。
- 原先失败的第 91,468 句迁移到第 90,596 句，资源与完整 `before/highlight/after` 上下文保持相同；迁移回归保留 777 ms 句内位置及原更新时间。
- 原书 7 个实际持久化 Locator、原创示例 5 个 Locator 的本地 DOM 重放共 12/12 通过：句子全文哈希一致，定位成功，只有当前一个装饰，高亮矩形非零，无 JavaScript 错误。共有原章节的导出字节保持一致。
- 发布前补充旧书迁移、单句流式读取和导入进度的 63 条正式回归，均在 256 MB JVM 堆限制下通过，包含约 120 MB 的来源表。真实原书另以旧解析器生成 182,937 句的 v2 索引，保存无文本/selector 的普通视觉进度，再迁移并重新打开，同一堆限制下通过：旧第 91,468 句映射到新第 90,596 句，视觉 Locator、更新时间和原 EPUB 字节保持不变。

临时原书探针和导出内容只留在本机临时目录，已从测试源码移除。浏览器检查与 Robolectric 测试不能代替 Android WebView 像素或真实 TTS 验证。
